## Core Principles

### 1. Trust Before Conversion

The primary objective is credibility. Users MUST trust the institution before they contact it. All design and content decisions MUST prioritize building trust over immediate conversion.

### 2. Real Content Before Decorative Design

Priority order for content:
1. Real Photos
2. Real Videos
3. Real Documents
4. Real Testimonials
5. Minimal Icons
6. Decorative Graphics

Authentic content MUST NEVER be replaced with AI‑generated visuals. Authenticity wins over aesthetics.

### 3. Institutional Identity

The website MUST NEVER be designed as:
- SaaS
- AI Startup
- Crypto Landing Page
- Generic Marketing Website

It MUST ALWAYS be designed as:
- Educational Institution
- Documentary
- Human
- Premium
- Professional

### 4. Homepage Philosophy

The homepage is the digital front lobby. Its responsibilities are:
- Build trust
- Present departments
- Guide visitors
- Encourage contact

It SHOULD NOT replace department pages; those are for detailed information and conversion.

### 5. Information Architecture

The site structure MUST follow this hierarchy:
- Homepage → Trust & Navigation
- Department Pages → Details & Conversion
- Blog → Activity & News
- Events → Community
- Student Portal → Services

Each section MUST have a clear, distinct purpose.

### 6. WordPress Architecture

The project MUST use:
- Custom WordPress Theme
- Modular template parts
- Reusable components
- RTL support
- Mobile‑first approach

Page builders and tightly coupled structures MUST be avoided.

### 7. Authenticity Rule

Whenever there is a conflict between aesthetics and authenticity, authenticity wins. This is a non‑negotiable principle.

### 8. Scalability

The architecture MUST support future integration of:
- Microsoft Forms
- Student Portal
- Online Registration
- Blog
- Events
- Additional educational departments

Design decisions SHOULD anticipate these extensions without requiring major rewrites.

### 9. Design Consistency

Every page MUST feel like part of one institution. Inconsistent styling or messaging that suggests multiple unrelated businesses is prohibited.

### 10. Non‑Negotiable Rule

Parents SHOULD feel comfortable visiting the academy in real life after seeing the website. The website MUST accurately represent the physical institution.

## Additional Requirements

- Technology stack: Custom WordPress theme with PHP, JavaScript, and CSS.
- RTL support: All templates MUST handle right‑to‑left languages.
- Mobile‑first: Responsive design starting from mobile viewports.
- Accessibility: WCAG 2.1 AA compliance SHOULD be targeted.

## Development Workflow

- All changes MUST be reviewed for compliance with the constitution before merging.
- Design reviews MUST verify authenticity, trust‑building, and institutional identity.
- Performance budgets: Pages SHOULD load within 3 seconds on 3G networks.
- Security: WordPress best practices for hardening MUST be followed.

## Governance

This constitution is the foundational governance document for the Novira Academy website. All design, development, and content decisions MUST comply with its principles.

Amendments require:
1. Documentation of the change and rationale.
2. Review by at least one stakeholder.
3. Update of dependent templates and guidance.

Compliance is reviewed during design critiques and code reviews. Non‑compliance MUST be justified in writing and tracked.
